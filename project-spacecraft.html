Spacecraftattitude control

A personal project: a MATLAB simulation of a small spacecraft that has to hold a pointing direction with reaction wheels that can only push so hard, and a safe mode that takes over when it starts to tumble. It runs in simulation only. None of it has been tested on hardware.

Outcome

I wrote the requirements first, then built the model, the controllers and the mode logic against them, and finished with a Monte Carlo harness that checks each requirement by ID.

  • 100%Monte Carlo trials that reached the detumble threshold within 60 s. The requirement was 95%. Each trial randomises the attitude (up to 120°), the rate (up to 8°/s per axis) and the disturbance torque.
  • 13.22°/sWorst angular rate seen across the trials, against a 15°/s safety limit.
  • ±0.003 N·mReaction-wheel torque limit per axis. Every controller output stayed inside it, checked separately from pointing accuracy.

Model

The spacecraft is a rigid body with a constant, diagonal inertia of 0.035, 0.040 and 0.025 kg·m² about its three axes. Attitude is a scalar-first quaternion, and the state also carries the body rates and the integral of the pointing error.

The rotational dynamics are the full nonlinear equations, J·dω/dt + ω × (J·ω) = τ, integrated with fourth-order Runge-Kutta. The quaternion drifts off unit length over a long run, so it is renormalised after every step. The reaction wheels are modelled as a torque limit of ±0.003 N·m on each axis, and every run carries a small constant disturbance torque, up to 2×10−5 N·m per axis.

Control

Three controllers share the loop. Detumbling is plain rate damping, τ = −Kd·ω, because at that point the only job is to stop the spin. For pointing there are two options:

  • A PID on the quaternion error. The error takes the short way round (its sign flips when the scalar part goes negative), and the integral only builds in nominal mode, so it cannot wind up while safe mode is in charge.
  • An LQR designed on the small-angle model, with Q = diag(2, 2, 2, 0.15, 0.15, 0.15) and R = 2000·I. The gain is also stored in the parameter file, so the project runs without the Control System Toolbox.

The LQR settles more cleanly near the target because it comes straight from the linear model. The PID is easier to reason about and tune. Early in a large manoeuvre neither gain matters much: the wheels saturate and the response is set by the torque limit.

Around the simulation I built an interactive MATLAB app. It sets the initial attitude and rates, the controller, safe mode on or off and a fault-injection window, then plays a 3D animation of the body frame and exports it as video, with the run saved as CSV. A short Python script checks the exported CSVs, and a C++ stub holds the controller in an embedded style.

Safe mode

The mode logic turned out to matter as much as the gains. With a single threshold the mode flaps: the rate hovers near the line and control switches back and forth. So entering and leaving use different thresholds, and every exit needs its condition to hold for a set time.

Mode transitions
FromToCondition
NominalSafe detumbleRate above 6°/s, or a fault active for 0.5 s
Safe detumbleSafe holdRate below 0.5°/s for 2 s
Safe holdNominalFault clear, rate below 0.5°/s, attitude error below 4°, and at least 8 s in hold

Two shortcuts are forbidden on purpose. Detumble cannot jump straight back to nominal, and nominal cannot drop into hold without detumbling first. Nothing returns to nominal while a fault flag is set.

Verification

Each requirement has an ID, and each test names the requirement it checks. The Monte Carlo harness runs 60 trials with a fixed seed and writes every run to CSV, so the numbers regenerate exactly.

The worst cases combine a large attitude error with a spin on more than one axis. The wheels saturate early in those, so the actuator sets the response rather than the controller. That is why the torque limit is checked on its own instead of being inferred from good pointing at the end.

Limits

This is a first version with its assumptions written down, and they bound what the results mean.

  • The controllers see the true simulated state. There is no sensor noise and no estimator; I kept both out of scope from the first week.
  • The wheels are a torque limit only, with no wheel speed, momentum build-up or friction.
  • The LQR is designed on a small-angle linearisation, so it is only valid near the target. The simulation itself stays nonlinear.
  • Disturbance torque is constant within each run.
  • The 3D spacecraft in the animation is a representative shape for watching the attitude, not a CAD model.

Adding sensor noise and an estimator would let the controller work from what a spacecraft could actually measure.
